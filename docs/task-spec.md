## 一、执行指令与项目目标

你是一名负责 MoonBit 基础软件项目交付的工程师。请在指定项目目录实现 **MoonXPT**：以 MoonBit 为主要实现语言的 SAS XPORT V5 数据读写库，以及配套命令行转换工具。

具体用户是需要在 MoonBit 程序中接入公开统计数据、检查 XPT 文件、保留数据语义并与其他统计软件交换数据的开发者。核心演示使用 CDC NHANES 的真实 XPT 文件。

完成以下工作流：

1. 读取真实 XPT 文件，查看数据集、列定义、标签和格式元信息。
2. 逐行读取数据，区分普通数值、字符串、普通缺失和带标记的特殊缺失。
3. 导出 CSV 与版本化的 JSON 元数据文件；用两者重建声明支持范围内的 XPT 文件。
4. 用独立实现验证读取和写入结果，提供可复现的错误案例和诊断。
5. 交付可复用 MoonBit 包、CLI、文档、必要测试、CI 配置与连续 Git 历史。

执行规则：

- 先检查当前仓库、用户已有改动、适用的 AGENTS.md 和工具链。只修改项目相关内容，保留用户改动。
- 如果指定目录尚不是仓库，先检查是否位于其他仓库中；在合适的项目目录初始化，不能误把父目录整体纳入项目。已有仓库优先复用。
- 默认按照阶段顺序持续实施；常规实现选择自行决定并记录理由，无须每个阶段重新询问是否继续。
- 每阶段满足验收条件后再进入下一阶段。遇到可修复问题继续修复；只有真实外部阻塞或影响既定目标的重大范围冲突才报告并请求所需信息。
- 如果用户只指定某阶段，完成该阶段并报告交接状态。恢复任务时读取进度文件和 Git 历史，接着做，避免重复初始化。
- 核心解析、数值转换、状态机、写入、CSV/元数据语义均由 MoonBit 完成。Python、R、C 仅用于开发期夹具和独立验证；发布的核心库与 CLI 不依赖这些验证程序。
- 交付本地代码和本地 commit。是否创建远程仓库、push、发布 Mooncakes 或提交赛事表单，依据当前会话已有授权；没有相关授权时准备好材料并清楚列出待发布步骤。
- 不把命令示例当作已执行结果，不把跳过的测试计为通过，不编造用户反馈、竞品结论、性能数据或提交记录。

## 三、信息来源与验证纪律

优先使用以下一手资料；在 `docs/references.md` 记录访问日期、参考实现版本或 commit，以及对应的用途：

1. [SAS XPORT V5/V6 文件布局说明](https://www.sas.com/content/dam/sasdam/documents/20260302/record-layout-of-a-sas-version-5-or-6-data-set-in-sas-transport-xport-format.pdf)：格式与边界条件依据。
2. [ReadStat](https://github.com/WizardMac/ReadStat) 及其 [XPORT reader](https://github.com/WizardMac/ReadStat/blob/dev/src/sas/readstat_xport_read.c)：独立读写行为、数值与缺失值验证参考。
3. [pyreadstat](https://github.com/Roche/pyreadstat) 与 [API 文档](https://ofajardo.github.io/pyreadstat_documentation/_build/html/index.html)：普通数据、元数据、独立生成文件的便捷验证入口。
4. [R foreign::read.xport](https://stat.ethz.ch/R-manual/R-patched/library/foreign/html/read.xport.html)：多成员文件的补充读取对照。
5. [CDC NHANES 2017—2018 人口统计数据](https://wwwn.cdc.gov/nchs/nhanes/search/DataPage.aspx?Component=Demographics&Cycle=2017-2018)：真实 XPT 输入起点。
6. [MoonBit 工具链文档](https://docs.moonbitlang.com/en/latest/toolchain/moon/tutorial.html)：根据安装版本确认构建、测试和包配置方式。
7. [赛事官网](https://moonbitlang.github.io/Hackathon2026/)：重新确认当期要求。前期访问时页面仍是十月信息，不能据此编造十一月截止日期。

需要特别处理的验证限制：

- pyreadstat 基于 ReadStat，二者不能算两个独立实现家族。
- 当前 pyreadstat 文档对特殊缺失值的支持有限，不能假定 `read_xport` 支持其他读取接口的同名参数。先检查固定版本的真实签名与结果；需要时使用仅供测试的 ReadStat C 回调适配器读取 missing tag。
- R `foreign::read.xport` 可用于多成员对照，但会将不同数值缺失值合并，并处理字符尾部空格。因此它不能证明缺失标记或原始字符字节得到保留。
- 先制作“特性—验证工具—工具限制”矩阵。某个参考实现不暴露某字段时，不能把该字段从验证报告里悄悄删除；补充独立字节向量或其他工具。
- 参考实现与规范冲突时记录最小复现和双方行为，依据规范与明确兼容策略解决，不能只为让测试通过而修改预期。
- 直接移植开源实现时保留对应版权与许可证，记录文件级来源。参考库、验证依赖、下载语料分别检查使用和再分发条件；GPL 验证工具不作为本项目运行时或复制源码的默认来源。

## 四、架构分层

以下是职责设计，不是已经存在的 MoonBit API。根据当前工具链选择实际接口和包布局，先验证再使用，禁止虚构标准库方法。

| 层 | 职责 | 依赖约束 |
| --- | --- | --- |
| L0：基础模型 | 元数据、缺失值、原始字节、选项、错误、带偏移的输入输出抽象 | 不依赖 CLI 或文件系统 |
| L1：二进制编码 | 整数、IBM 浮点、文本编码、记录布局、对齐和填充 | 依赖 L0；算法可独立测试 |
| L2：格式引擎 | V5 状态机、成员与变量解析、行读取、writer、资源限制 | 依赖 L0/L1；不依赖 CSV |
| L3：交换层 | CSV、版本化 JSON 元数据、类型校验、导入导出策略 | 使用 L2 公共 API |
| L4：使用入口 | 文件适配器、CLI 参数、退出码、用户诊断、示例 | 调用下层，不重复实现格式逻辑 |

独立验证脚本放在产品代码之外，不被 L0—L4 导入。

建议逻辑目录如下；实际 MoonBit 包声明以选定工具链为准，避免为每个小文件创建一个包：

```text
model/                 数据模型、错误、选项
codec/                 原始字节、浮点、字符与记录编码
reader/                V5 流式读取状态机
writer/                V5 写入与约束校验
exchange/              CSV 与 metadata JSON
cmd/moonxpt/           CLI 与平台 I/O
examples/              使用公共 API 的最小真实示例
tests/fixtures/        可再分发的小型夹具及来源清单
tools/                 获取语料、独立 oracle、比较和基准脚本
docs/                  设计、兼容性、验证、开发进度与交付材料
```

核心模型至少区分：

- `LibraryMetadata`、`DatasetMetadata`、`VariableMetadata`：包含成员标识及变量的显式存储属性。
- `NumericValue`：普通有限数值与 `Missing(tag)` 分开；原始编码字节可由读取 API 访问。
- `CharacterValue`：原始字节与按指定编码得到的文本视图分开；尾部空格策略明确。
- `ReadOptions` / `WriteOptions`：编码、限制、成员选择、歧义策略、确定性时间戳等。
- `XptError`：错误种类、文件字节偏移、成员、行、变量及原因；未知上下文允许为空，不能填造假位置。

逐行 API 可采用迭代器、回调或事件流，以 MoonBit 实际能力决定。调用者必须可以提前停止；输入接口须能正确处理短读、跨块数据和 EOF。禁止在“流式 API”内部先把整个文件或全部行装入数组。允许为未来的真实成员边界维护有界缓冲或临时文件，但须记录理由、资源上限与清理行为。

## 五、必须提前解决的技术问题

### 5.1 数值与缺失值

根据规范推导编码并用独立向量验证。覆盖正负数、零、指数边界、规范允许的缩短存储宽度、舍入和不可表示输入。NaN、Infinity 不能被静默映射成任意 SAS 缺失值；API 必须要求显式缺失类型或返回错误。

不能承诺 IBM 浮点经 IEEE Double 和 CSV 后总能逐字节恢复。明确区分：

- 原始字段字节访问；
- 约定精度下的数值语义往返；
- 整个文件的字节级复刻。

本次要求前两者，第三项不作为默认承诺。为一般浮点比较选择有依据的 ULP/绝对误差/相对误差规则；整数、标签、成员数、缺失标记和字符约定不使用模糊容差。

### 5.2 成员边界、行边界与填充

V5 数据区与末尾填充不能简单当作带显式行数的表来处理。对“短行全为空格”“末尾全空白字符行”“数据中出现类似头部的字节”“多成员切换”分别构造测试。

禁止全文件字符串搜索某个头部标记就直接切分成员。候选边界需要按状态、对齐、后续结构和字段约束验证。

对仅凭文件无法消除的歧义，默认返回可解释诊断；提供显式行数提示或有文档的兼容策略作为选项。不能宣称能从信息不足的文件里恢复唯一答案；也不能把所有 EOF 都当成正常完成而漏报截断。

### 5.3 编码、列标签与日期

原始字节是读取层的基础。ASCII 与 Windows-1252 文本转换须有双向测试；不认识的编码明确报告。字段宽度按编码后的字节数校验，超长输入默认报错，不能静默截断。

日期、时间、显示格式和标签保持元数据语义。提供通用数据交换能力，不实现猜测性的统计业务规则。

### 5.4 CSV 与 metadata JSON 的交换契约

在 S1 就确定并写入 `docs/exchange-format.md`，S4 按此实现：

- JSON 必须有 `schema_version`，包含成员标识、变量顺序、类型、标签、format/informat、目标编码、目标存储宽度和 CSV 约定。校验重复列、未知版本与不一致列数。
- CSV 使用 UTF-8、逗号分隔和双引号转义；明确换行和 BOM 策略；覆盖逗号、双引号、CR/LF、空串、前后空格。
- 数值列用 `.`、`._`、`.A`—`.Z` 表达相应缺失标记，有限数值采用足够精度、与 locale 无关的文本表示。类型由 JSON 决定，字符列中的 `.A` 必须仍是字符串。
- 数值空字段默认报错；如允许当作普通缺失，必须由显式选项启用。不能依赖自动类型猜测。
- 默认保留有意义的字符空格，任何 trim 选项都要在说明中标识其影响。不能在 CSV 中暗中转义或改写用户数据。
- 导出一个成员得到一对 CSV/JSON；多成员导出通过明确成员参数或逐成员执行。库 API 的多成员写入必须可用，CLI 本期可一次写一个成员。
- 单个 JSON 文件只保存列级与数据集级元数据，不能把所有单元格复制进去伪装成流式导出。
- 明确哪些头部字段重建或规范化；不宣称 CSV 往返后文件 hash 应相同。

任务：

1. 确认当前 MoonBit 版本、包配置格式和可用 I/O 能力，记录可复现安装方式。默认优先评估 native CLI；若当前稳定环境有实质限制，可选择经验证的 JS/Node CLI，并在 ADR 中说明运行依赖。只要求一个实际跑通的 CLI 后端，不能声称全后端支持。
2. 建立可编译模块、最小示例和按需测试入口，验证构建与测试命令真实可用。
3. 定义 L0 数据模型、错误结构、Reader/Writer 的公共行为与资源限制，使用 mock 输入验证短读、取消和错误传播。
4. 写明浮点、尾部歧义、字符编码、CSV/JSON、原始字段与语义往返契约。
5. 建立兼容性矩阵，逐项标记“未实现/已实现/已验证/不支持及原因”，不能提前全写成支持。

产物：可构建仓库、`docs/design.md`、`docs/compatibility.md`、`docs/exchange-format.md`、必要 ADR。

通过条件：选定后端构建通过；公共模型能表达全部缺失标记；接口不强迫全文件加载；后续测试有稳定的断言对象。

### S2：编码层与 V5 reader

按以下顺序实现，每个功能随代码添加相应测试：

1. 带边界检查的字节读取、整数、固定宽度字段和对齐处理。
2. IBM 数值编解码与全部缺失标记；保留原始数值字节的访问能力。
3. ASCII、Windows-1252 的显式编码视图及严格错误策略。
4. 库头、成员头、NAMESTR 与 OBS 的读取状态机，支持规范要求的描述符长度变体。
5. 按列存储位置读取数据行，检查溢出、越界、重叠或其他非法布局。
6. 流式输入、多成员、尾部填充与歧义策略；资源限制在分配内存前生效。
7. 给至少一个真实样本提供完整行扫描示例，记录解析结果。

通过条件：至少一个真实文件与参考实现的行列数及普通数据一致；数值与缺失值有独立向量；多成员夹具被正确枚举；截断和非法偏移报出结构化错误；改变输入 chunk 大小不改变结果。

### S3：V5 writer

任务：

1. 从显式 schema 生成合法头部与变量描述符，校验名称、标签、宽度、成员顺序和格式属性。
2. 逐行写入字符、数值及缺失值；处理对齐、成员切换和结束。覆盖空数据集与多个成员。
3. 默认用兼容的标准描述符布局输出；读取端支持的历史布局不必都成为 writer 可选输出模式，但须写明。
4. 时间戳等易变字段允许显式注入，固定输入和固定选项应产生稳定输出。
5. 对不可表示数值、编码失败、过长字段和 schema 不匹配给出错误。失败输出不能看起来是成功完成的文件。
6. 让独立工具读取 MoonXPT 生成的单成员和多成员文件；不能只运行本库 round-trip。

通过条件：独立工具可读取普通输出；schema 与值一致；特殊缺失字节检查正确；至少一个双成员输出由可处理多成员的独立实现读取。不能因某工具只处理首成员就把第二成员验证省略。

### S4：CLI 与数据交换

实现以下目标接口，参数的最终语法可以根据实际 CLI 库调整，但功能不能缺失；同步更新文档和命令测试：

```text
moonxpt inspect input.xpt --json
moonxpt inspect input.xpt --count-rows --encoding windows-1252
moonxpt export input.xpt --member DEMO_J --csv data.csv --metadata data.meta.json --encoding windows-1252
moonxpt write data.csv --metadata data.meta.json --output restored.xpt
```

任务：

1. `inspect` 输出成员、列定义、支持版本及诊断。未扫描数据时行数为未知；不能从文件大小或头部猜出一个数。
2. `export` 通过流式 reader 写 CSV 与 JSON，不累积所有行。
3. `write` 严格校验 JSON 与 CSV，按声明类型编码；字符 `.A` 与数值缺失 `.A` 分别处理。
4. CLI 的机器可读结果写 stdout；诊断写 stderr；定义成功、参数/格式错误、I/O 等退出码并测试。
5. 处理路径带空格、已存在输出、输入输出指向同一文件和转换失败。默认不覆盖已有输出；显式覆盖选项须安全处理。临时文件策略需要跨平台可解释。
6. 写下每种输出的失败语义，CSV 与 JSON 作为一组交付时不能静默遗留看似完整的半成品。

通过条件：真实样本完成 `inspect → export → write → 外部读取`；元数据与缺失值按契约保留；含引号、换行、空白、特殊标记的 CSV 正确；错误路径有一致退出码；命令示例实际运行。

### S5：真实文件与兼容性验证

任务：

1. 完成第七节测试矩阵，对至少 3 个真实公开文件执行逐列、逐值比较，不只核对前几行。
2. 完成独立输入到 MoonXPT、MoonXPT 输出到独立读取器、CSV/JSON 往返三条链路。
3. 对 oracle 无法保留的语义采用专门测试适配器或独立规范向量，并明确证据边界。
4. 在元数据长度、变量类型、数值字节、尾部和成员边界构造异常变体；可使用固定种子的变异测试。不能把进程崩溃、无限循环或无界分配当成普通失败。
5. 验证流式特性：分块输入、提前终止、重复放大数据行。记录输入规模、后端、耗时与峰值内存；测试数据放大属于合成负载，不冒称生产样本。
6. 修复发现的问题，并添加对应回归样例。每轮修复只重跑相关测试与必要的最终回归，不为了堆数量重复无意义测试。

产物：可复现脚本、`docs/validation-report.md`、`docs/benchmarks.md`、更新后的兼容性矩阵。

通过条件：所有 P0 有对应证据；误差与规范化规则明确；独立验证没有被 stub/mock 代替；资源使用不随总行数线性积累数据。如果外部工具尚不能运行，列为未验证，不能把 S5 标为完成。

### S6：交付与复现

任务：

1. 整理 README：用户场景、安装、公共 API、三条 CLI 命令、真实示例、支持矩阵、限制和参考来源。
2. 配置 CI：格式/静态检查、构建、单元与集成测试。小夹具测试可离线运行；联网真实语料验证单列任务，缓存并校验 hash。联网任务下载失败不得伪装为成功。
3. 固定工具链和 oracle 依赖版本；在干净临时检出或等效干净环境复现完整演示。
4. 准备一页赛事说明、演示脚本、许可证和第三方声明；根据当前官网整理待提交材料，避免把旧赛季要求当本期规则。
5. 审核 Git 历史，证明本次新增且保留至少 10 次有效 commit；更新交接说明。
6. 报告完成项、实际执行的检查、已知限制、项目路径、提交列表与发布状态。

通过条件：第九节全部满足；未完成的外部发布清楚列出，不能用“准备好发布”冒充“已经发布”。

## 七、测试与验证矩阵

测试围绕格式风险和用户工作流设计，不要求为简单转发函数凑单测数量。以下各项在验证报告中关联测试位置、命令及结果：

| 类型 | 最低覆盖 |
| --- | --- |
| 真实输入 | 至少 3 个公开 XPT、至少 2 类数据表，来源和 hash 可追溯 |
| 格式结构 | 头部、描述符变体、字段顺序与位置、跨块、空数据集、两个及以上成员 |
| 数值 | 正负数、零、精确整数、分数、指数边界、缩短宽度、不可表示输入 |
| 缺失 | 全部 28 种：普通 `.`、`._`、`.A`—`.Z`；与普通数值和字符标记区分 |
| 字符 | 空白、非 ASCII 编码、尾部空格、编码错误、字节宽度溢出 |
| 尾部 | 正常填充、截断、短行全空白、歧义选择、伪头部内容 |
| 交换 | CSV 引号/换行/逗号、空字段规则、元数据版本错误、类型与列数不一致 |
| 多成员 | 两个成员 schema 不同；读取、写入和选择导出均有证据 |
| 双向互操作 | 独立生成→MoonXPT；MoonXPT→独立读取；CSV/JSON→XPT→比较 |
| CLI | 路径、stdout/stderr、退出码、输出已存在、失败清理 |
| 稳健性 | 边界长度、整数溢出、超大声明、固定种子变异、不会无限循环 |
| 流式 | 小 chunk 与不齐边界、提前停止、读取量与内存观测 |

验证要求：

- 编解码共用同一段错误逻辑可能使内部 round-trip 通过，因此必须有规范向量与独立实现证据。
- 不用浮点容差掩盖缺失标记、行数、列位置或编码差异。
- 比较时显式关闭或归一化参考工具的日期自动转换、尾部空格处理等行为，保留比较策略说明。
- 真实数据不保证覆盖所有边界；合成向量补足边界，并标明来源类别。
- 记录失败用例的实际原因；不删除失败测试、放大容差或修改 golden 文件来掩盖问题。
